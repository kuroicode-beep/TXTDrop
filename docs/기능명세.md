## 1. 문서 개요

| 항목 | 내용 |
|------|------|
| 제품명 | TXTDrop |
| 기준 버전 | v0.6.1 |
| 대상 플랫폼 | Windows |
| 문서 목적 | 현재 구현 기준의 기능 범위와 동작 규칙을 정의 |

이 문서는 현재 저장소에 구현된 기능을 기준으로 작성한 명세서이다. 향후 기획 확장안이 아니라 실제 동작 중인 기능과 제약을 우선 기록한다.

## 2. 제품 개요

TXTDrop은 시스템 트레이에서 동작하는 Windows용 클립보드 저장 유틸리티다. 사용자가 지정한 전역 단축키를 누르면 현재 클립보드의 텍스트 또는 이미지를 파일로 저장한다. 텍스트 저장 시에는 Ollama를 이용해 AI 기반 파일명을 생성할 수 있다.

주요 사용 시나리오는 다음과 같다.

1. 사용자가 텍스트를 복사한다.
2. 전역 단축키를 누른다.
3. 앱이 저장 폴더에 `.txt` 파일을 생성한다.
4. 필요 시 AI가 텍스트 요약 제목을 파일명에 반영한다.

이미지 클립보드도 동일한 방식으로 `.png` 파일로 저장한다.

## 3. 핵심 기능

### 3.1 클립보드 저장

| 구분 | 입력 조건 | 저장 형식 | 결과 |
|------|-----------|-----------|------|
| 텍스트 저장 | 클립보드에 공백이 아닌 텍스트 존재 | `.txt` | UTF-8 텍스트 파일 저장 |
| 이미지 저장 | 클립보드에 이미지 존재 | `.png` | PNG 이미지 파일 저장 |
| 저장 불가 | 텍스트/이미지 모두 없음 또는 경로 미설정 | 저장 안 함 | 로그 기록, 상황에 따라 실패 토스트 표시 |

동작 우선순위는 이미지 우선, 텍스트 후순위다.

1. 먼저 `ImageGrab.grabclipboard()`로 이미지 여부를 확인한다.
2. 이미지가 있으면 이미지 저장 로직을 수행하고 종료한다.
3. 이미지가 없을 때만 텍스트 저장을 시도한다.

### 3.2 파일명 생성 규칙

#### 텍스트 파일명

기본 형식:

```text
{prefix}_{title}_{YYYYMMDD_HHMMSS}.txt
```

예외 형식:

```text
{prefix}_{YYYYMMDD_HHMMSS}.txt
```

세부 규칙:

1. `prefix`는 설정값 `filename_prefix`를 사용하며, 비어 있으면 `txtdrop`으로 대체한다.
2. Ollama 서버가 사용 가능하면 AI 제목 생성을 우선 시도한다.
3. AI 제목 생성 실패 시 텍스트의 첫 번째 비어 있지 않은 줄을 제목으로 사용한다.
4. 첫 줄 기반 제목은 Windows 파일명 금지 문자를 제거하고, 공백은 `-`로 치환하며, 최대 40자로 제한한다.
5. AI 기반 제목은 별도 정제 과정을 거치며 최대 50자로 제한한다.

#### 이미지 파일명

기본 형식:

```text
{prefix}_{YYYYMMDD_HHMMSS}.png
```

### 3.3 저장 폴더 규칙

| 항목 | 규칙 |
|------|------|
| 텍스트 저장 폴더 | `text_save_folder` 사용 |
| 이미지 저장 폴더 | `image_save_folder` 우선 사용 |
| 이미지 폴더 미설정 시 | 텍스트 저장 폴더로 대체 |
| 설정 경로가 존재하지 않을 경우 | 유효하지 않은 경로로 간주하고 저장 실패 처리 |

### 3.4 첫 실행 처리

앱 최초 실행 시 텍스트 저장 폴더가 비어 있으면 초기 설정 절차를 수행한다.

1. 안내 메시지를 표시한다.
2. 폴더 선택 대화상자를 연다.
3. 사용자가 폴더를 선택하면 텍스트/이미지 저장 폴더에 동일 경로를 저장한다.
4. 사용자가 취소하면 앱은 실행을 중단한다.

## 4. 단축키 기능

| 항목 | 내용 |
|------|------|
| 저장 단축키 (기본) | `Ctrl+Shift+Z` — 클립보드를 파일로 저장 |
| 낭독 단축키 (기본) | `Ctrl+Shift+X` — 클립보드 텍스트를 SVIL TTS로 낭독 |
| 적용 범위 | 시스템 전역 |
| 변경 가능 여부 | 설정 창에서 각각 변경 가능 |
| 저장 방식 | DB의 `hotkey` / `tts_hotkey` 값으로 유지 |

단축키 관련 규칙:

1. 앱 시작 시 저장된 단축키를 등록한다.
2. 등록 실패 시 각 기본값(`Ctrl+Shift+Z` / `Ctrl+Shift+X`)으로 한 번 더 시도한다.
3. 설정 창에서 단축키를 바꾼 뒤 저장하면 기존 단축키를 해제하고 새 단축키를 다시 등록한다.
4. 단축키 입력 캡처 시 `Ctrl`, `Shift`, `Alt` 중 하나 이상의 보조키가 반드시 포함되어야 한다.

### 4.1 클립보드 낭독 (SVIL TTS)

| 항목 | 내용 |
|------|------|
| 연동 서버 | SVIL TTS 프록시 `http://127.0.0.1:8765` |
| 엔드포인트 | `POST /api/tts/pipeline` (`category: narration`, `play_async: true`) |
| 텍스트 상한 | 2,000자 (초과분은 잘라서 낭독) |
| 전처리 | URL·코드블록·마크다운 기호 제거, 공백 정규화 (`tts_client._clean`) |
| 자동 기동 | TTS 프록시 미기동 시 SVIL 웹 백엔드 `http://127.0.0.1:3000/api/local-server`(`action:start, id:tts`)로 기동 요청 후 최대 60초 헬스체크 폴링 (MCP `svil_tts_speak`과 동일 경로) |
| 실패 처리 | 자동 기동 실패/타임아웃 시 오류 토스트 + `tts` 카테고리 로그 |

동작 흐름: 낭독 단축키 → 클립보드 텍스트 확인 → "음성 낭독 준비 중" 토스트 → (TTS 프록시가 꺼져 있으면 "TTS 서버 시작 중" 토스트와 함께 자동 기동·헬스체크 대기) → TTS 파이프라인 호출(생성 완료 후 워크스테이션 스피커 재생 큐 등록). 음성 생성은 백그라운드 스레드에서 수행되어 앱을 차단하지 않는다.

## 5. AI 제목 생성 기능

### 5.1 연동 대상

| 항목 | 내용 |
|------|------|
| 연동 서버 | Ollama |
| 기본 주소 | `http://localhost:11434` |
| 사용 목적 | 텍스트 저장 시 파일명용 짧은 제목 생성 |

### 5.2 동작 방식

1. 앱 시작 시 백그라운드에서 Ollama 실행 여부를 확인한다.
2. 서버가 실행 중이면 모델 목록을 조회한다.
3. 서버가 실행 중이 아니고 `ollama_autostart=true`이면 `ollama serve` 실행을 시도한다.
4. 텍스트 저장 시 캐시된 서버 상태를 기준으로 AI 제목 생성 가능 여부를 판단한다.
5. AI 사용 가능 시 사용자에게 "생성 중" 정보 토스트를 먼저 보여준다.
6. 모델 응답을 받아 정제한 뒤 파일명에 사용한다.
7. 실패하면 일반 텍스트 제목 규칙으로 자동 폴백한다.

### 5.3 모델 선택 규칙

설정값 `ollama_model`을 기준으로 실제 사용 모델을 해석한다.

우선순위:

1. 정확히 일치하는 모델명
2. `:latest`가 붙은 동일 이름
3. 접두사(prefix) 일치 모델
4. 조회된 첫 번째 모델

모델 목록 조회 실패 시 내부 기본 후보 목록을 사용한다.

기본 후보 목록:

- `llama3`
- `llama3.2`
- `phi3`
- `mistral`
- `gemma3`
- `qwen2.5`

### 5.4 시간 제약

| 항목 | 값 |
|------|----|
| 서버 상태 확인 타임아웃 | 2초 |
| 모델 목록 조회 타임아웃 | 5초 |
| 제목 생성 타임아웃 | 20초 |
| 서버 상태 캐시 TTL | 10초 |

### 5.5 자동 시작 설정

`ollama_autostart=false`이면 앱 시작 시 Ollama 상태 확인만 수행하고, 서버 자동 실행은 시도하지 않는다. 트레이 메뉴의 수동 새로고침은 설정값과 무관하게 사용자가 요청한 동작으로 처리한다.

## 6. 트레이 및 UI 기능

### 6.1 시스템 트레이

앱은 시스템 트레이 아이콘으로 상주 실행된다.

우클릭 메뉴 항목:

| 메뉴 | 기능 |
|------|------|
| Settings / 환경설정 | 설정 창 열기 |
| Log History / 로그 기록 | 로그/저장 이력 창 열기 |
| Deduplicate / 중복제거 | 중복제거 창 열기 (6.4 참조) |
| Refresh Ollama / Ollama 새로고침 | Ollama 상태 확인 및 필요 시 시작 |
| Exit / 종료 | 앱 종료 |

추가 규칙:

1. 가능하면 기본 Windows 메뉴 대신 다크 테마 커스텀 메뉴를 표시한다.
2. 커스텀 메뉴 적용 실패 시 pystray 기본 메뉴를 사용한다.

### 6.2 설정 창

설정 창은 단일 인스턴스로만 열 수 있다. 이미 열려 있으면 새 창을 띄우지 않고 기존 창을 전면으로 가져온다.

설정 항목:

| 섹션 | 항목 |
|------|------|
| 저장 폴더 | 텍스트 저장 폴더, 이미지 저장 폴더 |
| 파일명 | 파일명 접두사 |
| 단축키 | 저장/낭독 전역 단축키 캡처/변경 |
| AI | Ollama 모델, Ollama 자동 시작 |
| 중복제거 | 저장 시 자동 중복 검사 on/off |
| 사운드 | 저장 성공 시 효과음 |
| 언어 | 한국어, English |
| 데이터베이스 | DB 백업, DB 복원 |

설정 창 Ollama 상태 표시 규칙:

1. 설정 창을 열 때 `is_running()`으로 **실시간** 서버 상태를 확인한다. 캐시값(`is_running_cached`)을 사용하지 않는다.
2. 확인 결과를 공유 캐시(`_cached_running`)에 반영하여 이후 저장 동작에도 최신 상태가 적용되도록 한다.

언어 설정은 저장 즉시 DB에 반영되지만, 안내 문구상 재시작 후 완전 적용을 전제로 한다.

로그 창 역시 단일 인스턴스로 동작한다.

탭 구성:

| 탭 | 내용 |
|----|------|
| Log | 실행 로그 조회 |
| Save History | 저장 이력 조회 |

세부 기능:

1. 로그 탭은 최근 로그를 시간 역순으로 표시한다.
2. 로그 탭은 5초 주기로 새 로그 유입 여부를 확인하고 자동 새로고침한다.
3. 저장 이력 탭은 최근 저장 파일 500건을 표시한다.
4. 저장 이력 항목 더블클릭 시 실제 파일을 Windows 기본 연결 프로그램으로 연다.
5. 파일이 존재하지 않으면 경고 메시지를 표시한다.
6. 하단 버튼으로 로그 삭제, 수동 새로고침, 창 닫기를 수행할 수 있다.

### 6.4 중복제거 창

단일 인스턴스로 동작하며, 트레이 메뉴 "중복제거"로 연다.
DB의 history row만 이동하고 **실제 파일은 절대 건드리지 않는다** (원본 파일은 별도 보관 정책).

| 구성 | 내용 |
|------|------|
| 중복제거 실행 버튼 | 텍스트 저장 기록 전체를 오래된 순으로 검사, 중복 row를 `trash` 테이블로 이동 |
| 유사도 기준(%) | 70~100, 기본 90 — 실행 시 DB(`dedup_threshold`)에 저장 |
| 휴지통 목록 | 이동 시각·파일명·사유(기존 파일명 + 유사도 %) 표시 |
| 선택 복구 버튼 | 선택한 row를 history로 되돌림 (다중 선택 가능) |

중복 판정 규칙 (`dedup.py`):

1. 파일 내용을 읽어 공백 정규화 후 앞 4,000자만 비교한다.
2. SHA-256 해시가 같으면 완전 동일(100%)로 즉시 판정한다.
3. 해시가 다르면 `difflib.SequenceMatcher` 유사도가 기준치 이상일 때 중복으로 판정한다. 길이 차이가 큰 쌍은 조기 탈락시켜 속도를 확보한다.
4. 가장 먼저 저장된 문서를 원본으로 남긴다.
5. 파일이 삭제되어 읽을 수 없는 기록은 검사에서 건너뛴다.

저장 시 자동 검사 (`dedup_auto`, 기본 on):

1. 텍스트 저장은 평소대로 즉시 완료된다 (딜레이 없음).
2. 저장 직후 백그라운드 스레드가 기존 기록과 비교한다.
3. 중복 판정 시 방금 저장한 row를 trash로 이동하고 "중복 문서 정리" 토스트를 표시한다 (클릭 시 중복제거 창).

## 7. 알림 및 사운드

### 7.1 토스트 알림

토스트는 화면 우하단 작업 영역에 표시되며 여러 개가 위로 쌓이는 방식으로 배치된다.

| 유형 | 사용 상황 |
|------|-----------|

| 오류 | 저장 실패, 폴더 미설정, Ollama 설치/응답 문제 |
| 정보 | AI 제목 생성 중, Ollama 상태 알림 |

토스트 규칙:

1. 표시 시간은 5초.
2. 작업 표시줄을 침범하지 않도록 Windows 작업 영역 기준으로 위치를 계산한다.
3. 클릭 콜백이 있는 토스트는 클릭 시 로그 창을 연다.

## 8. 데이터 저장 구조

### 8.1 저장소

설정, 로그, 저장 이력은 실행 파일 기준 경로의 SQLite DB `txtdrop.db`에 저장한다.

실행 환경별 기준 경로:

1. PyInstaller 실행 파일 환경: 실행 파일이 있는 폴더
2. 소스 실행 환경: 현재 파이썬 파일이 있는 폴더

### 8.2 DB 스키마

#### `config`

| 컬럼 | 설명 |
|------|------|
| `key` | 설정 키 |

### 8.2.1 trash 테이블 (중복 문서 격리)

| 컬럼 | 내용 |

2. 복원 시 선택한 DB 파일 내용으로 현재 DB를 덮어쓴다.
3. 복원 후 메모리 캐시는 초기화된다.
4. 안내 문구 기준으로 복원 결과의 완전 반영은 앱 재시작을 전제로 한다.

## 10. 구현 제약 및 비고

1. 절전/복귀 이벤트 전용 핸들러는 현재 **비활성화(no-op)** 상태다. PyInstaller frozen 런타임에서 `WM_POWERBROADCAST` WNDPROC 패치 시 `STATUS_STACK_BUFFER_OVERRUN` 크래시가 발생하여, 안정성 우선으로 비활성화했다. 단축키는 Windows 훅 지속성에 의존한다.
2. 앱 종료 시 `os._exit(0)`으로 프로세스를 즉시 종료한다. `keyboard` 라이브러리의 논데몬 스레드가 `sys.exit()`만으로는 종료되지 않는 문제를 방지한다.
3. 첫 실행 폴더 선택은 `mainloop()` 시작 전 메인 스레드에서 `messagebox`/`filedialog`를 직접 호출한다. `call_on_main` + `event.wait()` 패턴은 데드락을 유발하므로 사용하지 않는다.
4. Tkinter `mainloop()`는 반드시 OS 메인 스레드에서 실행한다. pystray는 `run_detached()`로 백그라운드 스레드에서 동작한다.
5. Inno Setup 설치 시 `CloseApplications=yes`로 실행 중인 TXTDrop 프로세스를 자동 종료 시도한다.
6. 언어 문자열 일부는 소스 인코딩 상태에 영향을 받을 수 있으므로, 실제 배포본에서는 UI 문자열 검증이 필요하다.
7. 트레이 좌클릭 동작은 커스텀 우클릭 메뉴 패치 외의 pystray 기본 동작에 의존하므로, 명세상 핵심 기능으로 정의하지 않는다.
8. 명세는 2026-07-06 기준 저장소 구현(v0.6.1)을 반영한다.
