# 완료보고 — TXTDrop 중복 문서 제거 (trash 테이블 + 중복제거 창)

- 일자: 2026-07-08
- 작업자: Claude Code
- 브랜치: claude/svil-tts-mcp-shortcut-341aa2

## 요약

비슷한 내용의 중복 문서를 DB 차원에서 거르는 기능을 추가했다.
저장은 평소대로 즉시 처리하고(딜레이 없음), 백그라운드에서 중복을 판정해 history row를 `trash` 테이블로 이동한다. 실제 파일은 건드리지 않으며(원본 별도 보관 정책), 중복제거 창에서 언제든 복구할 수 있다.

## 변경 내역

| 파일 | 내용 |
|------|------|
| `dedup.py` (신규) | 중복 판정 엔진 — 공백 정규화 + SHA-256 완전 동일 검사 + difflib 유사도(조기 탈락 최적화), 전체 스캔 / 저장 후 자동 검사 |
| `dedup_window.py` (신규) | 중복제거 창 — 실행 버튼, 유사도 기준(70~100, 기본 90) 스핀박스, 휴지통 목록(이동 시각·파일명·사유), 선택 복구(다중 선택) |
| `config.py` | `trash` 테이블 신설, `history_move_to_trash` / `trash_get` / `trash_restore` / `history_rows`, `history_add`가 row id 반환, 기본값 `dedup_auto=true` / `dedup_threshold=90` |
| `main.py` | 트레이 메뉴 "중복제거" 추가(다크/네이티브 모두), 텍스트 저장 직후 `check_new_async` 백그라운드 검사 → 중복 시 토스트 |
| `settings_window.py` | "중복제거" 섹션 — 저장 시 자동 검사 on/off 체크박스 |
| `i18n.py` | dedup 관련 ko/en 문자열 |
| `docs/기능명세.md` | 6.4 중복제거 창, 8.2.1 trash 테이블, 기본 설정값·트레이 메뉴·설정 항목 갱신 |

## 판정 규칙

1. 파일 내용 공백 정규화 후 앞 4,000자 비교
2. 해시 동일 → 100% 중복
3. difflib 유사도 ≥ 기준치(기본 90%) → 중복. 길이 차이 큰 쌍은 조기 탈락(real_quick_ratio/quick_ratio 게이트)
4. 가장 오래된 문서를 원본으로 유지
5. 파일이 없는 기록은 건너뜀 (건수 보고)

## 검증

- 로직 테스트 (2026-07-08): 동일 문서 100% / 유사 문서 98% 판정·이동, 상이 문서 유지, trash 복구, 저장 후 자동 검사 콜백 — 전부 통과

## 참고

- trash는 DB row만 보관한다. 파일 삭제 기능은 의도적으로 넣지 않았다 (원본은 별도 보관).
- 유사도 기준은 중복제거 창에서 조정 가능하며 실행 시 DB에 저장되어 자동 검사에도 적용된다.
